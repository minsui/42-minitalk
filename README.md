# 📡 Minitalk

## 설명

**Minitalk**은 **UNIX 시그널**만을 사용하여 두 프로세스 간 통신을 구현하는 소규모 데이터 교환 프로그램입니다.

이 프로젝트의 목표는 저수준(low-level)에서 **프로세스 간 통신(IPC, Inter-Process Communication)** 이 어떻게 동작하는지 이해하는 것입니다. **서버** 프로세스는 신호를 수신 대기하고, **클라이언트** 프로세스는 메시지를 문자 단위로, 다시 비트 단위로 분해하여 `SIGUSR1`과 `SIGUSR2` 두 가지 시그널만으로 전송합니다.

### 동작 원리

- 메시지의 각 문자는 **8비트**로 분해됩니다.
- 클라이언트는 각 비트를 시그널로 서버에 전송합니다:
  - `SIGUSR1` → 비트 `0`
  - `SIGUSR2` → 비트 `1`
- 서버는 수신한 8개의 시그널로 문자를 재조합하여 표준 출력에 씁니다.

```
클라이언트                         서버
    |                               |
    |   SIGUSR1/SIGUSR2 (비트 단위) |
    |------------------------------>|
    |      (8개 시그널 = 문자 1개)  |
    |                               |
```

## 실행 방법

### 컴파일

`Makefile`을 사용하여 두 프로그램을 함께 컴파일합니다:

```bash
make
```

컴파일이 완료되면 `server`와 `client` 두 개의 실행 파일이 생성됩니다.

### 실행 순서

**1. 서버 실행**

```bash
./server
```

서버는 자신의 **PID(프로세스 ID)** 를 출력한 뒤 시그널을 대기합니다.

```
$ ./server
12345
```

**2. 클라이언트로 메시지 전송**

다른 터미널에서 서버의 PID와 전송할 메시지를 인자로 클라이언트를 실행합니다:

```bash
./client [서버_PID] "[메시지]"
```

**예시:**

```bash
./client 12345 "안녕, 42!"
```

서버는 시그널을 수신하여 메시지를 출력합니다:

```
안녕, 42!
```

### 유용한 시스템 명령어

| 명령어 | 설명 |
|---|---|
| `ps -ef` | 실행 중인 모든 프로세스의 이름과 PID 확인 |
| `kill -9 [PID]` | 해당 PID의 프로세스를 강제 종료 (`-9`는 kill 옵션 번호) |

## 핵심 개념

### PID (Process ID)
운영체제가 실행 중인 각 프로세스를 고유하게 식별하기 위해 부여하는 10진수 숫자.  
Minitalk에서는 클라이언트가 어떤 프로세스(서버)에게 시그널을 보낼지 지정하는 데 사용됩니다.

### 사용된 함수

| 함수 | 설명 |
|---|---|
| `getpid()` | 호출한 프로세스의 PID를 반환 |
| `signal()` | 특정 시그널에 대한 핸들러 함수를 등록 |
| `kill(pid, sig)` | PID가 `pid`인 프로세스에 시그널 `sig`를 전송 |
| `pause()` | 시그널을 수신할 때까지 프로세스를 일시 정지 |
| `usleep(n)` | `n` 마이크로초(μs) 동안 실행을 일시 정지 |
| `sleep(n)` | `n` 초 동안 실행을 일시 정지 |

### 사용된 시그널

| 시그널 | Minitalk에서의 의미 |
|---|---|
| `SIGUSR1` | 비트 `0` 을 나타냄 |
| `SIGUSR2` | 비트 `1` 을 나타냄 |

`SIGUSR1`과 `SIGUSR2`는 UNIX에서 프로그래머가 자유롭게 정의하여 사용할 수 있도록 예약된 사용자 정의 시그널입니다.
